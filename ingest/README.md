# VetAI Ingest

Строит тонкий индекс `data/index.db` (SQLite + FTS5) из S3-бакета. Идемпотентно:
пересоздаёт БД с нуля. S3 — источник правды, данные не мигрируются.

## Установка

```bash
pip install -r ingest/requirements.txt
```

## Переменные окружения

| Переменная    | Обязательна | Дефолт                        | Назначение                          |
|---------------|-------------|-------------------------------|-------------------------------------|
| `AK`          | да          | —                             | S3 access key                       |
| `SK`          | да          | —                             | S3 secret key                       |
| `S3_ENDPOINT` | нет         | `https://s3.twcstorage.ru`    | endpoint бакета                     |
| `S3_BUCKET`   | нет         | `lz810806-ai-data`            | имя бакета                          |
| `S3_REGION`   | нет         | `ru-1`                        | регион                              |
| `GALEN_LIMIT` | нет         | `0` (все)                     | ограничить число препаратов Galen   |

Ключи задаются только через env — в коде их нет. Пример см. `.env.example` в корне.

## Запуск

```bash
# Windows PowerShell
$env:AK="..."; $env:SK="..."; python ingest/ingest.py

# bash
AK=... SK=... python ingest/ingest.py

# быстрый прогон (только 50 препаратов Galen, для проверки схемы)
AK=... SK=... GALEN_LIMIT=50 python ingest/ingest.py
```

Полный прогон занимает ~4 минуты (обходит S3). Итоговый `data/index.db` ~101 МБ,
в git не коммитится (см. `.gitignore`).

## Эталонные счётчики (валидация)

После полного прогона в БД должно быть:

| Таблица        | Строк | Примечание                                   |
|----------------|-------|----------------------------------------------|
| `sources`      | 23    | 21 книга/руководство + 2 набора статей ВИК   |
| `pages`        | 5593  | единица чтения и цитирования                 |
| `toc`          | 9972  | 9572 `markdown` + 400 `curated` (см. ниже)   |
| `preparations` | 2438  | 79 `drugs` (чистые поля) + 2359 `galen`      |
| `diseases`     | 22    | 11 птица + 11 свиньи (из `.yml`)             |

`toc` по колонке `origin`:

| `origin`   | Строк | Источник                                                        |
|------------|-------|-----------------------------------------------------------------|
| `markdown` | 9572  | заголовки `#`/`##` из OCR-markdown (`extract_toc`)              |

`pdf_s3key` заполнен у 19 из 23 источников (у статей ВИК и справочных датасетов
PDF нет — там `NULL`).

## Онтология: курированные оглавления (`toc.origin='curated'`)

Шаг `ingest_ontology()` обогащает `toc` готовыми (курированными) оглавлениями из
дампов БД — **без какой-либо модели/LLM**, это чистый импорт данных.

- Источник: `VetAI/database_data/dumps/<hash>/source_document*.sql` — таблица
  `source_document(id, name, language, contents, created_at)`, где `contents` —
  готовое оглавление книги (по одной главе на строку). Файлы мелкие, кодировка UTF-8.
- Матчинг `source_document → sources`: по стабильной карте `id → slug` (`SDOC_SLUG`
  в `ingest.py`; имена в дампе на ru/en, slug'и — транслит, поэтому строковое
  сравнение их не связывает) + нормализованный фолбэк по имени. Несопоставленные
  логируются и пропускаются (падения нет).
- Уровень главы (`level`) определяется по числовой нумерации: `3.` → level 1,
  `3.1.` → level 2 и т.д. Номеров страниц в оглавлениях нет → `page_index = NULL`.
- Существующий markdown-`toc` не затирается: курированные строки добавляются рядом
  с `origin='curated'`.

Эталон после полного прогона: **18** из 19 файлов `source_document` сопоставлены с
книгами (**400** курированных строк `toc`); **213** записей уровня статьи из
`source_document_articles.sql` не сопоставляются (это отдельные статьи ВИК, а не
оглавления книг) и корректно пропускаются. Три slug-книги без курированного
оглавления (`avian_biocheck`, `pcr_test`, `guide_to_working_on_growing_and_fattening`)
не имеют записи `source_document` в дампах.

Идемпотентность: `build_schema()` пересоздаёт `toc` при каждом прогоне; парсинг
детерминированный — повторный запуск даёт те же счётчики.

Backend: `GET /api/sources/{id}/toc` возвращает и курированные записи; параметр
`?origin=all|curated|markdown` (дефолт `all`), поле `origin` в каждом элементе.

## Фактическая схема FTS (важно для API)

FTS-таблицы автономные (без `content='...'`), хиты сразу содержат ссылочные поля:

- `pages_fts(markdown, source_id UNINDEXED, source_title UNINDEXED, page_index UNINDEXED)`
- `preparations_fts(trade_name, generic_name, drug_class, target_animals, instruction_md, prep_id UNINDEXED)`
- `diseases_fts(name, body, disease_id UNINDEXED)` — колонка `body`, не `data_json`.

## Кодировка

Строки в БД хранятся в корректном UTF-8 (кириллица читаема). Ключи S3 в `pdf_s3key`
содержат не-ASCII символы в исходном виде — boto3 корректно подписывает их для
presigned URL. Отображение через терминал в cp866/cp1251 может выглядеть как
mojibake — это артефакт консоли, а не данных.
