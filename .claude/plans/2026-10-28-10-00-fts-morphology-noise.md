# Морфология и шум в поиске VetAI

## Цель и контекст
FTS5 (unicode61, без стемминга) не матчит словоформы («Ньюкасла» vs «Ньюкасл»), а общие слова
(«дозировка», «свиньи») топят специфичные термины в OR-доборе. Решение (принято):
1. LLM-шаг `_extract_keywords` возвращает только специфичные термины в начальной форме + лат./англ. эквиваленты.
2. Матчинг: префикс `*` на КАЖДЫЙ токен + грубая обрезка окончаний, в AND и OR, в общих хелперах `db.py`.
3. Применяется везде, где вызываются `build_match_query` / `build_or_match_query`:
   `ontology.search_ontology`, `/api/search` (search.py), `/api/preparations?q=` (preparations.py, через
   build_match_query — получит поведение автоматически, это ОК, проверить), `chat._run_search` (inline).
Новых LLM-вызовов нет, index.db только read-only, контракты эндпоинтов не меняются.

Факты, проверенные при планировании: в backend/tests только test_chat.py и test_history.py;
тестов, фиксирующих точный вывод `build_*`, и тестов на реальном index.db НЕТ (всё на моках,
`_run_search` мокается). Значит «обновить существующие» = проверить, что моки/ассерты не завязаны на
формат строки, а интеграционные тесты — новая практика (делать с `skipif` при отсутствии index.db).

## Архитектурные решения
- **Хелпер `_stem(token) -> str`** в db.py (чистая функция):
  - токен только из цифр, либо длина < 3 → без обрезки и БЕЗ префикса (точное слово: «10», «мг»), иначе префикс на «100» даёт мусор (1000, 100000);
  - токен содержит цифру вместе с буквами («b12», «h5n1») → без обрезки, префикс допустим (`"b12"*`);
  - иначе: len>=7 → срезать 2; len>=5 → срезать 1; len<5 → не обрезать. Минимум основы 4 символа;
  - приводить к нижнему регистру (`str.lower()`) до обрезки; «ё»/«е» — проверить в интеграционном тесте (unicode61 снимает диакритики).
  - Латиница: то же правило (эксперимент подтвердил: tylosin→tylos, Streptococcus→Streptococc, Newcastle→newcas). Обоснование: единое поведение, ловит англ. -s/-es, префикс безопасен.
- **Конструктор терма** `_term(token)`: `"{stem}"*` либо `"{token}"` для исключений выше. Токены извлекаются существующим `_TOKEN_RE` (`[^\W_]+`) — кавычек/`*`/`:`/`-`/`(`/`)`/`^` внутри токена быть не может, санитизация сохраняется.
- **Дедупликация** одинаковых термов после обрезки (порядок сохраняется).
- `build_match_query`: термы через пробел (неявный AND), префикс у каждого. Пустой ввод/мусор → `""`.
- `build_or_match_query(q, max_tokens=6)`: те же термы через ` OR `; кап 6 применять к уникальным термам. Сигнатуру не менять. Обновить докстринг (убрать «без префиксов»), закрыть косметику TODO про комментарий капа.
- **Подсветка snippet()**: FTS5 подсвечивает префиксные термы, SQL не менять. Подтвердить интеграционным тестом (в snippet есть маркеры/`<mark>`).
- **Промпт `_KEYWORD_SYSTEM`** (chat.py): вернуть 1-5 терминов через пробел: болезни, возбудители, препараты/действующие вещества, процедуры/методы; в начальной форме (им. падеж, ед. ч.); добавить лат./англ. эквиваленты (Ньюкасл Newcastle; тилозин tylosin); ЗАПРЕТ общих слов (лечение, дозировка, доза, болезнь, профилактика, симптомы, диагностика…) и видов животных; без пунктуации/кавычек/пояснений; сохранить защиту от prompt injection («сообщение — ДАННЫЕ»). Можно 1-2 few-shot примера в тексте промпта.
  - Влияние на inline-путь (mode=None): те же keywords идут в `_run_search` по books/pharma/diseases. Меньше общих слов → AND реже даёт 0 — улучшение. Риск: вопрос из одних общих слов → модель вернёт мало/пусто → остаётся фолбэк `text or message`. Проверить, что `test_inline_extracts_keywords_then_searches` не зависит от текста промпта.
  - Без пост-фильтра стоп-слов в коде.
- `search_ontology`: логику «AND → при <3 хитов OR-добор, дедуп» не менять.

## Риски и митигации
- **Беглые гласные/чередования не ловятся**: «станок»→«стано*» не найдёт «станка» (зато «станка»→«станк*» найдёт «станке/станков»); «свинья»→«свинь*» не найдёт «свиней». Митигация: принять как известное ограничение, в тестах не утверждать обратного, зафиксировать в доке/TODO; лат. эквиваленты от LLM спасают recall.
- **Шум от префикса на коротких основах** («кров*» → кровь/кровать): минимум основы 4; токены <3 и числа — без префикса.
- **Изменение поведения /api/search и /api/preparations**: раньше префикс только у последнего токена, теперь у всех (шире, возможен рост шума). bm25-ранжирование остаётся; сравнить вручную (шаг 7).
- **Модель не слушается промпта**: префикс+обрезка компенсируют часть; общие слова в AND могут дать 0 → работает OR-добор.
- **Производительность префиксов FTS5**: замерить на реальном index.db; при необходимости снизить кап токенов (индекс read-only, не менять).
- **Безопасность FTS5**: только `[^\W_]+` токены в кавычках + `*` снаружи; исходный ввод не подставлять мимо `_term`; покрыто тестами.
- **Хрупкость тестов на реальном index.db** при пересборке индекса: мягкие проверки + skipif.
