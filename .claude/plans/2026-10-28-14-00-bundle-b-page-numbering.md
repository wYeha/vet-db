# Пакет Б: единая нумерация страниц в аннотациях онтологии

## Цель и контекст

В `ontology/annotations/<slug>.md` заголовки глав выглядят как `### Название (стр A–B)`.
`ontology/load_annotations.py::parse` для всех книг считает `page_index = A-1`, `page_end = B`.
Но субагенты писали A по-разному: одни копировали `start` из `ontology/chapters/<slug>.json`
(это 0-based `page_index` из `map_chapters.py`), другие нумеровали с 1. `SUBAGENT_TASK.md`
конвенцию не задавал: шаблон `(стр A–B)` есть, а что такое A, не сказано. В итоге у 18 книг
из 23 старт главы стоит на 1 стр. раньше. У `modern_pig_farming` и
`practical_guide_to_broiler_health_management` первая глава получает **`page_index = -1`**.
Сейчас это гасят `_RANGE_MARGIN=1` и `_shift_fallback_start` в `backend/app/ontology.py`.

Цель: одна явная конвенция в файлах. Она совпадает с тем, что человек видит в UI
(фронт везде показывает `page_index + 1`). Загрузчик проверяет файлы, тесты на реальном индексе
не дают ошибке вернуться.

**Порядок:** пакет Б выполняется ПОСЛЕ пакета А (запасной путь, видовой буст, `<br>` в
`ontology.py`/`chat.py`). В `backend/app/ontology.py` Б меняет только комментарии и docstring.

## Исследование: фактическая конвенция по 23 книгам

**Метод.** Источник правды — `toc` в `data/index.db` (origin='markdown', level=1): это
`page_index` страницы, где в `pages.markdown` физически стоит `#`-заголовок. Эти данные выгружены
без изменений в `ontology/chapters/<slug>.json` (`markdown_headings[].page` и `chapters[].start`,
скрипт `map_chapters.py`). Для каждой главы аннотации заголовок сопоставлялся с якорем: по
названию, номеру главы («ГЛАВА 3-5», «26», «CHAPTER 4») или «Раздел N». Затем
сравнивалось A и page якоря: `A == page` — 0-based, `A == page+1` — 1-based.
Ограничение: у планировщика нет shell, поэтому sqlite напрямую не открывался, анализ сделан
по JSON-выгрузке того же индекса. **Шаг 1 плана перепроверяет таблицу прямым поиском
заголовка в `pages.markdown` (read-only).** Расхождение с таблицей — повод остановиться.

Стиль B (для миграции): **excl** — B = старт следующей главы (exclusive, 0-based);
**incl** — B = последняя страница главы (inclusive, 0-based, B = следующий A − 1).

**Итог:** внутри книги конвенция A **последовательная** везде. Смещения на титульные страницы
нет: A равно ровно `page_index` (0-based) или `page_index+1` (1-based). Непоследователен только
стиль B (inclusive/exclusive): смешан в `antimicrobial_usage_in_pig_production` и
`streptococcosis_dissertation`. Это решает правило по главам (ниже). Ещё одна аномалия
содержательная, а не смещение: `poultry_health_guide` «Avian Influenza (197–213)» перекрывается
с «Newcastle (206–213)». В этом пакете её не трогаем.

Ожидаемый offset для загрузчика после нормализации: **0 для всех 23 книг** (A 1-based → `page_index = A-1`).
Изменение `page_index` в `ontology_fts`/`/api/ontology/search` относительно текущего индекса: **+1 у 18
0-based книг**, 0 у пяти 1-based (`atrophic_rhinitis_of_pigs`, `avian_biocheck`, `pcr_test`, `vic_articles_*`).

## Архитектурные решения

1. **Чиним в файлах, вариант (а).** Все 23 аннотации приводятся к одной конвенции:
   «`стр A–B`: A = первая страница главы, B = последняя страница главы **включительно**,
   обе 1-based, как в UI (= `page_index + 1`)». Загрузчик (`A-1`, `B` raw = exclusive 0-based)
   уже соответствует этой конвенции, его формула не меняется.
   - Почему не (б) таблица offset в загрузчике: файлы останутся с «невидимой» конвенцией. Человек
     правит аннотацию по номеру из читалки (1-based) и в 0-based-файле снова ошибётся.
     Таблицу нужно синхронизировать с каждой новой книгой.
   - Почему не (в) автодетект: хрупко. Есть OCR-мусор в заголовках («Gитоnocнaя cвumomattка»,
     «Финишный пывок»), сборники статей, книги без якорей (atrophic B/C). Результат непрозрачен
     и может меняться при пересборке индекса.
   - (а) прозрачно (видно в diff и в самом файле) и воспроизводимо: миграция — коммит со
     скриптом, индекс пересобирается загрузчиком. Риск ограничен: меняются только числа в
     скобках заголовков, проверка до и после.
2. **Маркер конвенции в каждом файле.** Первая строка:
   `<!-- pages: 1-based; стр A–B = page_index+1, B включительно -->`. Миграция пропускает
   файлы с маркером (идемпотентность). Загрузчик предупреждает, если маркера нет.
3. **Миграция — одноразовый скрипт в репозитории** `ontology/normalize_annotation_pages.py`.
   Таблица 0-based-книг и стиль B по умолчанию **захардкожены** по таблице выше, без автодетекта.
   Есть `--dry-run` (печать diff заголовков) и `--apply`. Преобразование для 0-based-книги, по
   главам, в порядке файла (учитываются только главы с A):
   - `A' = A + 1`;
   - B есть: `next_A` — A следующей главы с `A > текущего A`.
     Стиль книги incl → `B' = B + 1`.
     Стиль excl → `B' = B + 1`, если `B == next_A - 1` (глава записана inclusive), иначе `B' = B`.
     Обоснование: exclusive 0-based конец численно равен inclusive 1-based последней странице.
   - B нет («стр. 70») → только `A'`.
   - Заменяются только числа внутри совпадения того же регэкспа, что в `parse`
     (`стр\.?\s*(\d+)(?:\s*[–—-]\s*(\d+))?`, первое вхождение в строке `###`). Остальной текст
     заголовка (тире, «стр.», «(Глава 1, …)», «(Chapter 3)») сохраняется побайтно.
   - Для «смешанных» книг стиль `antimicrobial_usage_in_pig_production` задать excl. Правило
     `B == next_A - 1` само поймает inclusive-главы 3/5/6/7.
   - 1-based-книгам только добавить маркер, числа не трогать.
4. **Загрузчик:** формула та же. Добавить чистую функцию
   `validate_chapters(chapters, num_pages) -> list[str]`: `page_index < 0`,
   `page_index >= num_pages`, `page_end > num_pages`, `page_end <= page_index`. Плюс проверка
   маркера. `main()` печатает предупреждения, флаг `--strict` → exit 1. Docstring `parse`:
   убрать «ВНИМАНИЕ: конвенция смешанная», описать единую конвенцию.
5. **Компенсации в `ontology.py` оставить как страховку, значения не менять.**
   - `_RANGE_MARGIN = 1`. После нормализации ошибка ±1 из-за 0/1-based уходит. Остаются
     другие источники неточности: главы без якоря (`start=null`), которые субагенты выравнивали
     вручную («±1–2 стр не важны», `SUBAGENT_TASK.md`, `PILOT.md`); главы, начинающиеся в
     середине страницы (текст на странице `start-1`); OCR-заголовки, перетекающие на соседнюю
     страницу. Цена запаса — 1 лишняя страница с каждой стороны для BM25. Уменьшение до 0
     ломает recall на этих главах и задевает пакет А. Меняем только комментарий: причина —
     «неточные границы глав (ручное выравнивание/середина страницы)», а не «смешанная конвенция».
   - `_shift_fallback_start` оставить. Он закрывает реальный кейс «старт главы на странице
     литературы предыдущей главы», который возможен и при верной нумерации (глава начинается
     внизу страницы со списком литературы). Срабатывает только на фолбэках, стоит один точечный
     запрос. Меняется только docstring и комментарий в `refine_ontology_hits` («из-за ±1» →
     «если старт пришёлся на литературу предыдущей главы»).
   - Существующие тесты `test_ontology_refine.py` и `test_chat.py` проверяют эти функции на
     синтетике и не меняются.
6. **`/api/ontology/search`:** контракт полей тот же. Значения `page_index` у 18 книг станут
   на 1 больше: это исправление. Внешний скилл получит правильные старты. Записи в `history.db`
   со старыми хитами онтологии будут ссылаться на страницу раньше. Миграцию истории не делаем,
   фиксируем в docs.

## Риски и митигации

| Риск | Митигация |
|------|-----------|
| Таблица в плане неверна для какой-то книги (анализ по JSON-выгрузке, не по тексту страниц) | Шаг 2: прямая проверка по `pages.markdown` до миграции, при расхождении стоп. Шаг 7: проверка после |
| `atrophic_rhinitis_of_pigs`: у B/C нет якорей | Вердикт по книге (A. Введение — однозначно 1-based). Если check-скрипт покажет иное для B/C — поправить эти две главы вручную и отметить в отчёте |
| Миграция повредит текст заголовков/аннотаций | Замена только чисел внутри регэкспа `parse`; `--dry-run` и ревью diff; `newline=""`; git-откат |
| Повторный запуск миграции сдвинет ещё на +1 | Маркер в файле + пропуск размеченных файлов + юнит-тест идемпотентности |
| Люди/субагенты снова напишут 0-based | Маркер, обновлённый `SUBAGENT_TASK.md`, предупреждения загрузчика, `--strict` в check-скрипте |
| Конфликт с пакетом А в `ontology.py`/ARCHITECTURE | Б идёт после А. В `ontology.py` только комментарии. ARCHITECTURE правится поверх версии А |
| `page_index` в `/api/ontology/search` и в UI-ссылках сдвинется | Это исправление, контракт тот же. Фиксируется в ARCHITECTURE. Старые записи `history.db` не мигрируются (осознанно) |
| `index.db` не пересобран → тесты на `ontology_fts` врут | Регрессия читает файлы аннотаций и `pages`. Проверка `ontology_fts` только при свежем индексе (иначе skip с подсказкой) |
| Перекрытия глав (Influenza/Newcastle) | Вне скоупа. Миграция сохраняет их как есть, `validate_chapters` их не запрещает |
